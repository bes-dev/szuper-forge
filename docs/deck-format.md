# Szuper Deck Format

Снимок контракта upstream Szuper; пути к мобильному коду относятся к
репозиторию [bes-dev/Szuper](https://github.com/bes-dev/Szuper), а не к harness.
Здесь используются `szuper-forge` и модуль `src/szuper_forge/dialogue.py`.

Спецификация реализованного формата, редакция 1.0 от 2026-11-17.
Диалоговое расширение имеет независимую версию `data-version="1"`.
Редакция этого документа не является полем Anki-пакета.

## 1. Область действия

Szuper использует обычный контейнер Anki `.apkg`. Отдельного расширения файла,
обязательного Szuper-манифеста и обязательной модели заметок нет.

| Уровень | Содержимое | Назначение |
|---|---|---|
| Обычная Anki-колода | Basic, Reversed, Cloze, медиа, теги | Автоматически строящиеся упражнения и классический режим |
| Справочная заметка | Basic + `szuper::reference` + HTML | Теория, не участвующая в повторениях |
| Диалог v1 | Forward Basic + `szuper::dialogue` + структурированный Back | Единый плеер, синхронные реплики и авторский квиз |

**Требование парсера** описывает, что принимает текущая реализация.
**Профиль новых эпизодов** — более строгие правила авторинга, обеспечивающие
полноценный синхронный UX. Унаследованный допустимый документ может не иметь
всех новых возможностей. Рекомендации по педагогике не являются синтаксическими
ограничениями. Не считать произвольный HTML, JS-шаблоны или все расширения Anki
поддержанными только потому, что контейнер Anki корректен.

## 2. Контейнер, модели и поля

### 2.1 Архив

ZIP содержит коллекцию SQLite и manifest `media`, сопоставляющий архивные имена
(обычно `0`, `1`, …) реальным плоским именам медиа. Импортёры выбирают коллекцию
в порядке `collection.anki21b`, `collection.anki21`, `collection.anki2`.
Поддерживаются legacy JSON-конфигурации/schema 11 и modern protobuf/schema 18,
распаковывание zstd коллекции, manifest и медиа. Это возможности импортёров;
для наиболее переносимой генерации использовать legacy `collection.anki2`
с JSON `media`, например через genanki. Экспорт приложения также legacy.

Все необходимые записи, изображения, CSS и шрифты включать в архив. Онлайн-ссылка
не заменяет локальное медиа. Для переносимости — уникальные имена файлов без
подкаталогов, `/`, `\`, `:`, `%`, NUL, `.` и `..`. Имена в HTML и manifest должны
совпадать с учётом регистра. Практично включать ID эпизода и хеш записи в имя.

### 2.2 Заметка и карточка

Anki note имеет GUID, упорядоченные поля и теги. Card ссылается на note и ordinal
шаблона. Basic обычно создаёт одну карточку ordinal 0; Reversed — несколько
направлений с отдельным состоянием памяти; Cloze — карточки индексов `c1`, `c2`, …
(ordinal = индекс − 1). Одна карточка не равна одному полю или одной реплике.

Для обычных заметок приложение извлекает текст из шаблонов: `{{Field}}`,
`{{FrontSide}}`, условные `{{#Field}}` / `{{^Field}}` и cloze. Большинство других
фильтров не воспроизводится полноценно. CSS/JS обычных шаблонов не определяют
нативный интерфейс. При отсутствии пригодного шаблона используется fallback
первого и второго непустых полей. Не полагаться на этот fallback при авторинге.

Для **reference и dialogue** действуют позиционные правила:
**поле 0 — Front/заголовок, поле 1 — Back/HTML**, независимо от имён полей.
Импортируется только ordinal 0. Для новых заметок использовать один forward
Basic-шаблон, не обратную модель и не Cloze. Не совмещать reference и dialogue
в одной заметке; сейчас ветка dialogue имеет приоритет, это не полезный контракт.

### 2.3 Именованные роли полей

Рекомендуемые имена приведены первыми. Импортёры распознают и перечисленные
алиасы; выбирать одно поле на роль, не рассчитывать на порядок слияния дубликатов.

| Поле | Алиасы | Смысл |
|---|---|---|
| Front | Через Anki-шаблон у обычных заметок | Вопрос; у специальных заметок — заголовок в позиции 0 |
| Back | Через Anki-шаблон у обычных заметок | Ответ; у специальных заметок — исходный HTML в позиции 1 |
| Hint | Подсказка | Настоящая помощь до ответа |
| Extra | Back Extra, Explanation, Additional, Пояснение, Дополнительно, Комментарий | Дополнительный разбор после ответа |
| Source | Sources, Источник, Источники, Provenance | Происхождение, ссылки, авторство и способ генерации |
| Examples | Example, Примеры, Пример | Примеры применения; у старого аудирования — транскрипт |
| Audio | Не отдельная семантическая роль импортёра | Удобное обычное поле с `[sound:filename.mp3]` |

Имена вспомогательных полей сравниваются без учёта регистра. Source не является
Hint, проверяемым ответом или текстом для TTS. Source хранится как авторская metadata,
не выводится в learner templates, подсказке, разборе ответа и читателе теории.
В названиях/учебном HTML не должно быть путей к исходникам, статусов извлечения
или заголовков «получено из PDF»; сырые OCR/архивы остаются авторским приложением. Известные старые строки `Источник:`
и `Source:` из Hint/Extra отделяются как provenance; не использовать это вместо
правильного поля в новых колодах. Третье поле само по себе не означает Hint.
Обычные аудио-ссылки `[sound:...]` и изображения `<img src="...">` распознаются
при очистке HTML. У обычной карточки нативное представление не сохраняет весь
исходный дизайн шаблона или все произвольные поля.

### 2.4 Ответы обычных карточек

Один проверяемый смысл — одна карточка. Альтернативные ответы можно разделять
` / ` или `;`; первая форма должна быть полноценной и пригодной для показа и
озвучивания. Скобочные пояснения не должны нести единственный смысл ответа.
Cloze записывается канонически: `{{c1::answer}}` или `{{c1::answer::hint}}`.
Задания и дистракторы обычных карточек строятся локально: авторский quiz JSON
для словаря не требуется. Длинное объяснение помещать в reference, применение
правила — в отдельную Basic/Cloze-карточку. Типы доступных упражнений зависят
от пригодности содержимого, размера пула и настроек занятия, а не только тегов.

## 3. Теги и темы

Теги — стандартные Anki-токены без пробельных символов. `::` задаёт иерархию,
`_` отображается пробелом. Обычный тег становится темой. Несколько тегов связывают
одну карточку с несколькими темами без дублирования её памяти. У заметок без тем
источником группировки служит подколода. Все темы доступны сразу.

| Тег | Значение |
|---|---|
| `Grammar::Questions` | Обычная тема «Grammar › Questions» |
| `szuper::topic::<name>` | Старый явный канал темы; новые колоды могут использовать обычные теги |
| `szuper::reference` | HTML-справка, исключённая из упражнений/очереди/освоения |
| `szuper::dialogue` | Полный авторский эпизод аудирования v1 |
| `szuper::material::theory` | Назначение reference: правило/объяснение |
| `szuper::material::lexicon` | Словарные справочные данные, без отдельного раздела интерфейса |
| `szuper::material::lesson` | Оригинал/допматериал урока |
| `szuper::material::guide` | Инструкция или сведения о колоде |
| `szuper::section::<key>` | Группа правил справочника |
| `szuper::order::<integer>` | Порядок главы внутри справочника |
| `szuper::type::vocab\|cloze\|fact\|term\|rule` | Необязательный тип знания; значение — один из перечисленных вариантов |
| `szuper::confuse::<group>` | Узкая группа путаемых ответов для дистракторов |
| `szuper::listening` | Старый формат выделенного аудирования |
| `szuper::audio-language::<BCP-47>` | Объявленный язык аудио; при наличии имеет приоритет в ListeningMaterial |
| `szuper::listening-target::<value>` | Старое текстовое уточнение цели аудирования |

Служебные теги `szuper::…`, `marked`, `leech` темами не становятся; исключение —
явный `szuper::topic::…`. Неизвестные служебные теги не создают автоматически
новых возможностей. Использовать нижний регистр для имён служебных тегов и
значений enum; пользовательские темы сохраняют авторский регистр. Не задавать
несколько противоречащих тегов одной роли. Не записывать проценты освоения,
уровни доступа или ежедневные лимиты в теги.

## 4. Теоретический справочник

Обычная Basic-заметка: Front — заголовок, Back — HTML-фрагмент, теги
`szuper::reference szuper::material::theory` и темы связанных упражнений.
Материал исключён из очереди и знаменателя освоения, чтение не создаёт FSRS-review.
Путь интерфейса: «Теория → правило». Группы — заголовки плоского списка.

Встроенные section keys: `foundations`, `nouns`, `cases`, `verbs`, `numbers`,
`sentences`, `usage`, `other` в этом порядке. Другие значения — авторские группы;
пробелы кодировать `_`. `szuper::order::10` задаёт целое число, иначе используется
порядок карточек. У старых материалов назначение/раздел также угадываются по
заголовку; новым явно задавать metadata, не полагаться на язык заголовка.

Читатель поддерживает HTML-заголовки, абзацы, списки, таблицы, цитаты, aside,
изображения, `<style>`, inline CSS, локальные CSS и шрифты. Использовать гибкую
ширину, читаемые подписи и совместимость со светлой/тёмной темой. JS выключен;
CSP и навигационная политика запрещают iframe, сеть и внешние переходы. Не
создавать главы, зависящие от JavaScript, внешних стилей или веб-сервисов.
Содержимое обычного PDF не становится автоматически HTML-учебником.

```html
<h1>Вопросительные слова</h1>
<p>Выберите слово в зависимости от того, что хотите узнать.</p>
<aside><strong>Где?</strong> — вопрос о месте.</aside>
<table><tr><th>Пример</th><th>Перевод</th></tr>
<tr><td>Where do you live?</td><td>Где вы живёте?</td></tr></table>
<img src="question-map.svg" alt="Схема выбора вопроса" />
```

Для словарных данных поддержан блок `<section class="lexicon-entry">` или
`<article class="lexicon-entry">`: первый `h2`/`h3`/`h4` — слово, обычные `p` —
определение, `blockquote` — примеры, `p.source` — источник. Старые классы `hu-lex`
и `hu-source` также распознаются. Такие данные не создают самостоятельное меню
словаря; тематическая лексика для занятий остаётся обычными карточками.

## 5. Диалог: HTML v1

### 5.1 Модель

Одна forward Basic-заметка с `szuper::dialogue` = один эпизод и одна итоговая
оценка памяти. Front — заголовок, Back — **один** XML-корректный HTML-фрагмент
`article`. `Audio` с `[sound:master.mp3]` рекомендуется для воспроизведения в Anki;
источником нативного master остаётся атрибут article.

HTML — декларативные данные, не исполняемый шаблон интерфейса. Парсеры чувствительны
к регистру имён элементов, атрибутов и enum. Закрывать теги (`<br />`), экранировать
`&`, `<`, кавычки в атрибутах. Только стандартные XML entities (`&amp;`, `&lt;`,
`&gt;`, `&quot;`, `&apos;`) и числовые ссылки; `&nbsp;` без DTD некорректен.
Не вставлять `[sound:...]` внутрь текста реплики: потомки входят в её текст.

### 5.2 Прямые потомки и атрибуты

Таблицы описывают парсер. Вложенность существенна: нужные узлы ищутся среди
**прямых детей**, не произвольно во всём дереве. Текст элемента — объединённый
текст потомков с удалением пробелов по краям; структурные границы сами не вставляют
пробел. Вставлять их явно между inline-узлами.

| Узел/атрибут | Требование парсера | Профиль новых эпизодов |
|---|---|---|
| `article` | Корень; `data-kind="dialogue"`, `data-version="1"` | Обязательно |
| `article > h1` | Первый, непустой | Равен Front по смыслу |
| `article > [data-kind="intro"]` | Опциональный текст | Короткая инструкция без раскрытия ответов |
| `article@lang` | Отсутствует/пустой → `und` | Объявить реальный исходный BCP-47 |
| `article@data-translation-lang` | Опциональный | Объявить язык переводов |
| `article@data-audio` | Опциональное безопасное локальное имя master | Обязательно для синхронизации |
| `article@data-duration` | Опциональное конечное число > 0 секунд | Реальная длительность master, обязательна |
| `article > section[data-kind="segment"]` | 1–32 части | Смысловые части с одним вопросом каждая |
| `section@data-id` | Непустой, уникален в эпизоде | Стабильный смысловой ID |
| `section > audio@src` | Первый audio, безопасное локальное имя, обязателен | Реальная запись этой части, даже если есть master |
| `section > [data-kind="transcript"]` | Контейнер прямых `p`, минимум одна фраза | Обычно `div` |
| `section > [data-kind="translation"]` | Опциональный общий перевод части | Полезен для классического Anki/совместимости; не заменяет перевод фраз |
| `section > fieldset[data-kind="question"]` | Один используемый вопрос (первый fieldset) | Один вопрос на понимание |
| `section > [data-kind="explanation"]` | Опциональный текст | Короткое объяснение правильного ответа |

Дублировать используемые одиночные узлы не следует: парсер использует первый,
а не объединяет их. Неизвестная версия отвергается; неизвестные узлы обычно
игнорируются как структура, но их текст может входить в значение родителя.
`data-pronunciation-system` — авторская metadata, текущий runtime её не интерпретирует.

### 5.3 Реплика

Каждый прямой `p` внутри transcript — одна фраза. Её ID в runtime вычисляется
как `<segment-id>-<zero-based-phrase-index>`; отдельного авторского ID фразы в v1 нет.

| Данные | HTML | Правило |
|---|---|---|
| Текст | Текст `p` | Непустой, точно соответствует записи |
| Говорящий | `data-speaker` | Парсер допускает отсутствие/пустоту; новым указывать имя или роль |
| Перевод | `data-translation` | Опционален для парсера; новым давать каждой фразе, без показа по умолчанию |
| Произношение | `data-pronunciation` | Опциональная IPA/авторское чтение; runtime показывает без преобразования |
| Система произношения | `data-pronunciation-system` | Опциональная metadata, например `ipa`; runtime пока не сохраняет её отдельно |
| Начало/конец | `data-start`, `data-end` | Секунды в master; оба сразу или ни одного |
| Отдельная запись фразы | `data-audio` | Опциональное безопасное имя локального файла |

Пронумерованные части и их фразы образуют единый плоский таймлайн в порядке HTML.
Не разбивать предложение только ради эстетики строк; текст переносится интерфейсом.


### 5.3.1 Перевод отдельных слов (необязательное расширение v1)

Внутри transcript `p` можно размечать слова прямыми дочерними `span`:

```html
<p data-speaker="A" data-start="3.548" data-end="5.8778" data-translation="Рядом с макаронами.">
  A <span data-gloss="макароны" data-lemma="tészta">tészták</span> mellett.
</p>
```

`data-gloss` — непустой перевод именно написанной формы в контексте реплики;
`data-lemma` — необязательная словарная форма. Язык перевода наследуется из
`article@data-translation-lang`; приложение не подставляет языковую пару.
Сохранять исходный текст, пунктуацию, пробелы, времена, медиа и IDs. Повторные
вхождения могут иметь разные переводы. Для нового выпуска с этой функцией
разметить каждое слово, исключая разделительную пунктуацию и пробелы.
Для языков без пробелов автор задаёт границы слов, приложение их не угадывает.
Допустимы осмысленные устойчивые сочетания в одном span.

Не вкладывать gloss span друг в друга и не помещать перевод в текст span:
`itertext(p)` должен дословно совпадать с произносимой фразой. Нативные парсеры
вычисляют UTF-16 диапазоны по фактическому положению span в смешанном XML-тексте,
поэтому emoji, диакритика и повторяющиеся слова не меняют выбранное вхождение.
Неизвестная/пустая gloss-аннотация не мешает старому читаемому тексту в runtime;
валидатор нового выпуска отвергает пустой перевод.

Слова с переводом имеют пунктирное подчёркивание. Тап выделяет слово, ставит
воспроизведение на паузу и открывает привязанное к нему облачко. Тап другой
реплики сохраняет обычную навигацию с остановкой и перемоткой; просмотр слова
не раскрывает полный перевод реплики. Облачко закрывается по тапу снаружи,
возобновлению воспроизведения, смене реплики и переходу к вопросам. Просмотр
перевода до ответа учитывается как помощь для соответствующей части; после
ответа повторный просмотр оценку не меняет. Старые колоды без span работают
как раньше. Обычный Anki продолжает показывать исходный текст.

Полный перевод реплики открывается только отдельной кнопкой «Перевод фразы».
Не назначать его фону строки, пробелам, пунктуации или жесту выбора реплики:
это конфликтует с точным нажатием на слово. Свободное место активной строки
ничего не раскрывает; выбор другой строки — только остановка/перемотка.

### 5.4 Квиз

`fieldset > legend` — непустой вопрос. Прямые `label` — варианты, 2–8 штук.
`label@data-id` непустой и уникальный в вопросе. Тексты непустые и уникальные
после trim. `data-correct="true"` — точное строковое значение для правильного
варианта; остальные значения считаются false. Новым писать явные `true`/`false`.

| `fieldset@data-type` | Проверка |
|---|---|
| `choice` (значение по умолчанию) | Ровно один правильный из 2–8 |
| `true-false` | Ровно два варианта, один правильный; тексты задаёт автор |
| `select` | Хотя бы один правильный и хотя бы один неправильный; точный набор |

Никакого произвольного кода проверки или полей свободного диктанта в v1 нет.
Можно задавать язык вопросов/вариантов по педагогической задаче; отдельного
атрибута quiz-language runtime не использует.

## 6. Аудио, таймкоды и языки

**Синхронный режим** включён, когда есть master и у **каждой** фразы start/end.
Все метки — секунды в одной окончательной master-записи. Не смещения в файле
части, не миллисекунды, не индексы символов.

Требования: конечные `start >= 0`, `end > start`, неубывающие start в порядке
всех фраз, master объявлен. При указанной duration принимается `end <= duration +
0.05` (допуск парсера). Парсер допускает перекрытия и одинаковые start; новый
авторинг должен избегать неоднозначного перекрытия и иметь строго возрастающие
start. Промежутки тишины разрешены. Подсветка использует последнюю фразу,
начавшуюся не позже текущего времени; пауза однократного прослушивания — её end.

Парсер может принять документ без duration или с частью нетаймированных фраз;
он **не** гарантирует синхронный UX. Для новых карточек обязательны master,
измеренная duration и полные тайминги всех фраз. `section > audio` обязателен
даже с master. Отдельные clips фраз не обязательны для синхронного replay.
Файлы MP3 удобны для переносимости; декодирование других форматов зависит от ОС.

Языковые пары не зашиты в приложении: исходный язык и язык перевода приходят
из Anki-данных. Запись проигрывается без угадывания языка. Для TTS нужен известный
язык и доступный голос; неизвестный язык не превращается в произвольный default.
`und`/отсутствие означает неизвестный язык. Письменность сама по себе не задаёт
язык. Произношение хранится в карточке; автоматическая IPA не равна выверенной
фонетической транскрипции конкретного диктора. Происхождение указывать в Source.

Старый формат `szuper::listening` использует обычные поля: Examples — транскрипт,
Extra — перевод, аудио — стандартное медиа, опционально audio-language/target.
Он остаётся читаемым, но не получает настоящую пофразовую синхронизацию без
диалоговых данных и таймингов. Новые длинные задания создавать как dialogue v1.

## 7. Поведение и оценка

Один плеер и один синхронизированный reader: play/pause всего эпизода, предыдущая/
следующая фраза, перемотка, скорость 1×/0.8×/0.6× и однократное проигрывание фразы.
По завершении одной фразы плеер ставится на паузу на её end, выделение остаётся
на ней. Повторы не создают отдельную карточку или review.

Ручной выбор другой реплики останавливает любое воспроизведение и ставит позицию
на её start. Тап по уже активной реплике переключает её перевод без перемотки;
есть inline-подсказка жеста. Переход к другой реплике закрывает видимый перевод,
в том числе при автоматическом продвижении звука. История использованной помощи
при этом не стирается. Оригинал и произношение включаются как помощь в том же
reader. Ручной скролл прекращает автоследование, но сам не останавливает звук;
возврат к текущей фразе восстанавливает следование.

Выход/фон прекращает звук; возврат не запускает его сам. Position, cue, speed,
помощь и ответы хранятся в checkpoint приложения, **не в HTML колоды**.
После изучения диалога пользователь явно переходит к вопросам; принудительно
прослушивать весь файл перед ними не требуется.

| Итог эпизода | Оценка FSRS |
|---|---|
| Все вопросы верны, без текстовой помощи | Good |
| Не менее 75% верных либо все верны с помощью | Hard |
| Менее 75% верных | Again |

Каждый вопрос проверяется по точному набору правильных ID. Видимая правильность
ответов остаётся честной: помощь ограничивает оценку памяти, не делает верный
ответ неправильным. Чтение оригинала, произношения или перевода до ответа
учитывается как помощь; скрытие после чтения не отменяет её. Чтение после
зафиксированного ответа не меняет его evidence. Незавершённый эпизод и replay
не записывают дополнительные оценки. Один завершённый эпизод — один review.

## 8. Идентичность, обновления и экспорт

### 8.1 Авторский источник

Для обновлений исходной колоды сохранять GUID заметки и ordinal шаблона.
В пределах существующей колоды Szuper сопоставляет карточки по этим данным;
текст, теги и медиа можно обновлять, сохраняя память. GUID не выводить из
изменяемого заголовка. Стабильные deck/model IDs полезны для Anki. Не считать
переименованный корневой deck гарантированно тем же объектом приложения.

Для dialogue сохранять также section IDs и option IDs. Фразы определяются
позициями внутри section: вставка или перестановка меняет их идентичность для
checkpoint. V1 не умеет семантически мигрировать уже начатый эпизод при подобном
редактировании. Завершённая карточка всё ещё опознаётся по GUID.

### 8.2 Границы экспорта

Экспорт — перенос учебного содержимого и текущего состояния памяти, **не побитовая
копия исходной Anki-базы**. Исходные произвольные модели, JS/CSS шаблонов и все
поля не гарантируются. Экспорт использует модель Szuper Basic с Front, Back,
Hint, Extra, Source, Examples; медиа прикладываются. Содержимое dialogue Back и
reference HTML сохраняется, как и теги и перечисленные роли полей.

Есть существенные текущие различия платформ:

- **iOS:** каждый обычный StudyCard экспортируется отдельной forward-заметкой,
  GUID — `<original-guid>#<templateOrdinal>`. Dialogue сохраняет исходный GUID.
  Обратные/Cloze карточки могут быть развёрнуты в Basic. Поэтому экспорт обычной
  колоды и её реимпорт нельзя обещать как обновление тех же GUID исходного Anki.
- **Android:** экспорт группирует по исходному GUID, использует forward/reversed
  шаблоны. Это также не восстановление произвольной исходной модели/Cloze.
  Точные параметры FSRS, журнал и scheduling не следует считать побитово
  эквивалентными iOS или оригинальному Anki.

Checkpoint плеера и незаконченный квиз не являются стандартными данными `.apkg`
и не переносятся как продолжение эпизода на другом устройстве. Для выпуска
обновлений хранить авторский JSON/исходную Anki-колоду и стабильные ID, а не
использовать экспорт приложения как гарантированно без потерь редакторский master.

### 8.3 Scheduling и собственный прогресс

Колоду можно выпускать без истории: новые карточки начнут собственную FSRS-память
в приложении. В `.apkg` с scheduling стандартные type 0/1/2/3 означают
new/learning/review/relearning; due для review — дни от `col.crt`, для intraday
learning — epoch seconds, для day learning — номер дня от создания коллекции.
Interval хранится в днях; reps/lapses передают счётчики повторений.

iOS при первом импорте новой идентичности использует FSRS `s`/`d` из JSON
`cards.data`, а при их отсутствии оценивает память из интервала/SM-2 ease.
При обновлении существующей идентичности локальная память не заменяется
привезённым расписанием. Android также создаёт начальное состояние из интервала
и ease; его текущий импортёр не читает FSRS `s`/`d` из `cards.data`.
Не обещать точное совпадение прогнозов с исходным Anki после переноса.

Отрицательная queue используется как suspended/buried и исключает карточку из
занятий, но есть legacy-ограничение iOS: для `type=0` scheduling сейчас не
создаётся и отрицательная queue новой карточки не переносится этим путём.
Reference исключается по назначению независимо от авторского расписания.
Новые диалоги выпускать доступными для изучения; исключение теории задавать
reference-тегом, а не попыткой кодировать её как скрытое упражнение.

## 9. Валидация и ограничения

### 9.1 Реальные ограничения парсеров dialogue

- Back не более **2 000 000 UTF-8 байт**.
- Максимальная глубина дерева — 32 элемента, число элементов — менее 10 000.
- Запрещены `<!DOCTYPE`, `<!ENTITY`, `<script` без учёта регистра (проверка подстрок).
- Только корень article с указанными kind/version; 1–32 уникальные части.
- Любая ошибка обязательной структуры, таймингов или вариантов отвергает эпизод.
  Некорректный dialogue HTML приводит к ошибке импорта, не к молчаливой конвертации.
- Синтаксическая корректность не доказывает наличие/декодируемость всех медиа,
  точность перевода, записи и таймингов. Проверять отдельно.

### 9.2 Ограничения архивов

| Платформа | Защитные пределы текущего импортёра |
|---|---|
| iOS | ≤100 000 ZIP entries; ≤2 GiB суммарного распакованного ZIP; ≤1 GiB копируемых распакованных медиа |
| Android | ≤512 MiB распаковываемой ZIP entry/медиа; ≤1 GiB суммарно распакованного ZIP; отдельный лимит 32 MiB на декодирование modern media manifest |

Это защитные пределы, а не рекомендованные размеры колоды. Архив с избыточными
медиа может иметь разное поведение на платформах; включать нужные ресурсы и
проверять реальный импорт. Не рассчитывать на восстановление отсутствующего
файла из интернета. Колоды с reference могут сохранять дополнительные media
ради CSS/шрифтов, но это не универсальная гарантия сохранения всех лишних файлов.

### 9.3 Проверка выпуска

1. Структурная валидация HTML и карточек, уникальные GUID/IDs, допустимые имена.
2. Manifest содержит каждое используемое медиа, файл не пуст и декодируется.
3. Master duration измерена; границы реплик проверены относительно окончательной записи.
4. Каждый перевод соответствует своей фразе; вопросы имеют однозначный ответ в аудио.
5. Открытие в Anki: Front/Back, media, без зависимости от Szuper JS.
6. Импорт в Szuper: темы, синхронизация, подсказки, replay, квиз, результат.
7. Реимпорт исправленной авторской колоды с теми же GUID сохраняет память.
8. Отдельная проверка экспорта/импорта с учётом §8.2, без обещания сохранения всех моделей.

`scripts/dialogue_deck.py` рядом со скиллом проверяет **новый синхронный профиль**
и генерирует legacy `.apkg`. Это инструмент авторинга, не замена всем проверкам
нативного импортёра и не универсальный валидатор чужих Anki-колод.

## 10. Полный минимальный dialogue-пример

Демонстрационная структура; файлы и таймкоды для реальной колоды должны быть
подготовлены по записи. Front: `At the café`. Теги:
`szuper::dialogue Everyday::Cafe`. Audio: `[sound:cafe-master.mp3]`.
Source: авторство записи, дата, способ генерации/проверки произношения.

```html
<article data-kind="dialogue" data-version="1" lang="en"
         data-translation-lang="ru" data-audio="cafe-master.mp3" data-duration="6.0">
  <h1>At the café</h1>
  <p data-kind="intro">Послушайте, что заказывает посетитель.</p>
  <section data-kind="segment" data-id="cafe-order">
    <audio controls="controls" src="cafe-order.mp3"></audio>
    <div data-kind="transcript">
      <p data-speaker="Customer" data-start="0.2" data-end="2.4"
         data-translation="Чай, пожалуйста."
         data-pronunciation="tiː pliːz" data-pronunciation-system="ipa">Tea, please.</p>
      <p data-speaker="Server" data-start="2.8" data-end="5.7"
         data-translation="Конечно. С молоком?">Of course. With milk?</p>
    </div>
    <div data-kind="translation" hidden="hidden">Чай, пожалуйста. Конечно. С молоком?</div>
    <fieldset data-kind="question" data-type="choice">
      <legend>Что заказал посетитель?</legend>
      <label data-id="tea" data-correct="true">Чай</label>
      <label data-id="coffee" data-correct="false">Кофе</label>
    </fieldset>
    <p data-kind="explanation">Посетитель говорит: «Tea, please».</p>
  </section>
</article>
```

### Источники реализации

Пути от корня репозитория; при изменениях формата сначала сверять эти места:

- `ios/Packages/SzuperKit/Sources/SzuperKit/Anki/{AnkiCollection,ApkgImporter,ApkgExporter,AnkiTemplateRenderer}.swift`
- `ios/Packages/SzuperKit/Sources/SzuperKit/Session/{NoteContent,CardAnnotations,MaterialLibrary,ListeningMaterial,DialogueEpisode,DialogueTimeline}.swift`
- `ios/App/Sources/ViewModels/LessonViewModel.swift`, `ios/App/Sources/Views/DialogueExerciseView.swift`
- `android/data/src/main/java/com/szuper/data/anki/{ApkgImporter,ApkgExporter}.kt`
- `android/core/src/main/kotlin/com/szuper/core/{DialogueEpisode,DialogueTimeline}.kt`
- `android/app/src/main/java/com/szuper/app/ui/screens/DialogueEpisodeScreen.kt`

Формат HTML версии 1 нельзя расширять обязательными данными, которые старый
парсер интерпретирует иначе. Новые обязательные возможности требуют версии
формата и согласованных изменений обоих парсеров, генератора, спецификации и
проверок. Дополнительная авторская metadata может игнорироваться runtime; её
наличие само по себе не добавляет интерфейсную функцию.


### Ordered textbooks in Szuper

Use a learner-facing title such as `A2 · Перенести встречу` in Front and the chapter heading.
Use the same topic name on the chapter and its study notes, with underscores for spaces.
Keep episode Front, the dialogue heading and the level tag consistent.

An optional integer tag `szuper::course-order::<N>` on a theory chapter orders its
study topics and its section in the native apps. When multiple chapters share a topic
or section, the earliest rank wins. Explicit ranks come first; unranked items use the
existing fallback order. Use `szuper::order::<N>` for the chapter's reading order
within its section. Numbers need only appear in metadata. Stable practice groups
continue to select the same exercises across a chapter rename.

Szuper Forge keeps evidence and production notes by GUID in the author project. Its distributed .apkg retains an empty Source field for model compatibility. The importer can still read provenance from other Anki packages.
